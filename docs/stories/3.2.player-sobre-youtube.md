# Story 3.2 — Player sobre YouTube

**Épico:** 3 – Player próprio (`docs/prd/epic-3-player.md`) · **Status:** InReview
**Executor:** @dev · **Quality gate:** @architect

## História
Como assinante, quero assistir ao episódio com controles próprios (não os do YouTube), para ter a
experiência do produto, não a do YouTube.

## Critérios de aceite
- [x] Interface `VideoSource` (`load, play, pause, seek, currentTime, duration, on(event)`) em
      `src/components/player/`, pronta para outro provedor (Bunny) entrar depois sem reescrever o player (NFR6).
- [x] `YouTubeSource`: IFrame API, host `youtube-nocookie.com`, parâmetros
      `controls=0&rel=0&iv_load_policy=3&disablekb=1&playsinline=1&modestbranding=1`; camada transparente por
      cima do iframe impede clique direto nele (controles do YouTube ficam inacessíveis).
- [x] Componente `Player`: controles próprios — play/pause, barra de progresso (clicável/arrastável), volume,
      velocidade (0.5×–2×), tela cheia; atalhos de teclado (espaço, setas, M, F) e gestos no touch
      (tocar para pausar/retomar).
- [x] Usa `GET /api/play/{episodeId}` (story 3.1) para obter `{ provider, ref }`; nunca recebe nem expõe o
      `video_ref` fora dessa chamada.
- [x] Página de teste dentro do admin (`/admin/titulos/{id}/.../assistir`) para o Gustavo conferir o player
      num episódio de verdade, sem depender da página pública (Épico 8, ainda não existe).

## Escopo
- **Dentro:** `VideoSource`/`YouTubeSource`, componente `Player` com controles, atalhos/gestos, página de
  teste dentro do admin.
- **Fora:** progresso/retomar/próximo episódio (story 3.3), legendas/pular abertura (story 3.4), eventos de
  reprodução (story 3.5), página pública do título (Épico 8), `BunnySource` (sem vídeo Bunny no catálogo ainda).

## Dependências
- Story 3.1 (`/api/play`) — Done.
- Story 2.3 (episódios com `video_ref`) — Done.

## Complexidade
- **Alta.** Primeira integração com a IFrame API do YouTube; controles customizados e atalhos exigem cuidado
  com estado e eventos do `postMessage` da API.

## Riscos
- **Termos da API do YouTube:** não esconder a marca/o player por completo — a arquitetura já aceita o risco
  de aviso/encerramento do canal, mitigado por manter a identidade visual do YouTube minimamente visível
  (o player não pode, por exemplo, cobrir o vídeo com um elemento opaco — só uma camada transparente para
  capturar cliques). Ver `docs/architecture/index.md`, "Riscos aceitos com o YouTube".
- **API do YouTube carrega de forma assíncrona e pode falhar/atrasar:** o player precisa de um estado de
  carregamento e tratar erro (vídeo removido, bloqueado por região, API não carregou) sem travar a tela.
- **Teclado/gestos conflitando com a página:** atalhos só devem funcionar com o player em foco/visível, não
  globalmente na página.

## Notas de desenvolvimento
- **Não inventar funcionalidade do YouTube além do permitido:** os parâmetros do iframe já estão
  especificados na arquitetura (`docs/architecture/index.md`, "Player") — não adicionar parâmetros extras
  sem necessidade.
- **Formato de tempo, barra de progresso etc.:** lógica pura (sem DOM) deve ficar em funções testáveis
  separadas do componente React, seguindo o padrão já usado em `src/lib/` (ex.: `datetime-local.ts`,
  `youtube.ts` da story 2.3) — mais fácil de testar com Vitest.
- **Reaproveitar `parseYoutubeId`?** Não — aqui o `video_ref` já vem pronto de `/api/play`; `parseYoutubeId`
  (story 2.3) é só para o admin, ao cadastrar o link.
- **Página de teste fica dentro do admin** propositalmente (ver Escopo) — evita inventar uma rota pública
  antes do Épico 8 decidir como ela deve ser.

## Notas de desenvolvimento (implementação)
- **Não dividiu em duas stories** (o @po tinha dado essa opção) — T1–T4 couberam numa sessão só sem
  atropelar os testes/typecheck/lint.
- **`host: "https://www.youtube-nocookie.com"`** passado direto no construtor do `YT.Player` — é a forma
  documentada da IFrame API de usar o domínio sem cookies (não precisa trocar a URL do script `iframe_api`,
  só esse parâmetro na criação do player).
- **Tipos da IFrame API:** não existe `@types/youtube` instalado; criei um `.d.ts` mínimo
  (`youtube-types.d.ts`) só com o que o `YouTubeSource` usa, em vez de adicionar uma dependência nova.
- **Camada transparente:** é um `<button>` cobrindo o player (bloqueia clique no iframe), mas só quando
  `state === "ready"` — durante carregamento/erro ela some, para não capturar cliques inúteis nem esconder
  a mensagem de erro.
- **Tela de erro não vaza detalhe técnico:** qualquer falha (401/403/404/429/erro do YouTube) vira uma de
  duas frases genéricas — "Não foi possível carregar este episódio." ou "Não foi possível reproduzir este
  vídeo." — nunca o código de erro cru do `/api/play` nem do YouTube.
- **`parseYoutubeId` (story 2.3) não é usada aqui** — o player já recebe o `video_ref` pronto de
  `/api/play`, como a story pedia para não reaproveitar.
