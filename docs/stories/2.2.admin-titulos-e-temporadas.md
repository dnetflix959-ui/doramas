# Story 2.2 — Admin: títulos e temporadas

**Épico:** 2 – Catálogo e admin de conteúdo (`docs/prd/epic-2-catalogo-e-admin-de-conteudo.md`) · **Status:** Done
**Executor:** @dev (+ @data-engineer no T1) · **Quality gate:** @architect

## História
Como Gustavo, quero cadastrar e publicar títulos (com tradução em pt/en/es) e suas temporadas pelo admin,
para montar o catálogo sem escrever SQL.

## Critérios de aceite
- [x] `/{idioma}/admin` e as páginas abaixo dele só abrem para admin; visitante ou assinante comum é
      redirecionado (igual às outras áreas protegidas, story 1.3).
- [x] Lista de títulos (`/admin/titulos`): mostra tipo, slug, status e destaque; link para criar e para cada título.
- [x] Formulário de criar título: tipo (`series`/`movie`), slug, status (`draft`/`scheduled`/`published`),
      destaque, data de agendamento, e nome+sinopse em pt/en/es.
- [x] Formulário de editar título: mesmos campos, exceto o tipo — **não pode ser alterado depois de criado**
      (fecha o achado REQ-001 do QA gate da story 2.1 também no banco, com um trigger).
- [x] Título do tipo série mostra a lista de temporadas, com criar e apagar (apagar bloqueado se a temporada
      já tiver episódios).
- [x] Erros de validação aparecem no formulário (slug em formato inválido ou já em uso, campos obrigatórios).

## Escopo
- **Dentro:** página de admin para títulos e temporadas (CRUD), trigger de banco que impede trocar `kind` com
  conteúdo existente.
- **Fora:** episódios (story 2.3), legendas/mais traduções de episódio (story 2.4), páginas públicas do
  catálogo (Épico 8), upload de imagem de capa (sem campo de imagem nos critérios de aceite — avisar se precisar).

## Dependências
- Story 2.1 (schema do catálogo) — Done. Usa `titles`, `title_translations`, `seasons`.
- Story 1.3 (auth, `is_admin()`) — Done (falta só Google OAuth/marcar admin, que são passos do Gustavo,
  não bloqueiam esta story).

## Complexidade
- **Média.** Duas páginas com formulário (criar/editar unificados), upsert de traduções por idioma, CRUD de
  temporadas, mais uma migration pequena (trigger).

## Riscos
- **REQ-001 (gate da story 2.1):** sem o trigger em `titles.kind`, mesmo que a UI não ofereça o campo editável,
  alguém com acesso direto ao banco (ou um bug futuro na UI) poderia trocar o tipo de um título com conteúdo.
  Por isso o trigger é um critério de aceite aqui, não só uma recomendação de UI.
- **Upsert de tradução:** uma linha por `(title_id, locale)` já existe (constraint `unique` da story 2.1);
  salvar o formulário precisa fazer `upsert` nas 3 traduções, não `insert` (senão falha na segunda vez que
  o Gustavo editar o mesmo título).
- **Apagar temporada com episódios:** a FK de `episodes.season_id` é `on delete cascade` (story 2.1) — apagar
  a temporada apagaria os episódios em silêncio. Por isso o AC exige bloquear a exclusão quando há episódios,
  em vez de confiar no cascade.

## Notas de desenvolvimento
- **Padrão de Server Action + formulário:** seguir `src/app/[lang]/entrar/actions.ts` + `login-form.tsx`
  (`"use server"`, `useActionState`, `Input`/`Button` de `src/components/ui/`). Erros de validação voltam no
  estado do `useActionState`, iguais ao padrão de `MagicLinkState`.
- **Checar admin no servidor:** não existe helper ainda; chamar `(await createClient()).rpc('is_admin')` no
  layout do admin (a função já existe desde a story 1.3, sem `revoke execute`, então está disponível).
  Se quiser um helper, criar `src/lib/supabase/admin.ts` com uma função `requireAdmin()` que redireciona.
- **Proxy já protege `/admin`** (ver `protectedPaths` em `src/proxy.ts`, story 1.3) — isso só garante login,
  não que a pessoa é admin; o layout do admin é quem checa `is_admin()`.
- **Slug:** mesma regra do banco (`^[a-z0-9]+(-[a-z0-9]+)*$`, até 80 caracteres) — validar no formulário antes
  de enviar para dar erro amigável em vez do erro cru do Postgres.
- **Traduções:** `title_translations` tem `unique (title_id, locale)` — usar `upsert` do Supabase
  (`onConflict: "title_id,locale"`), uma chamada por idioma ou um array de 3 linhas numa chamada só.
- **Não inventar:** nenhum campo além do que está nos critérios de aceite (ex.: sem campo de imagem/capa —
  não está no schema da story 2.1 nem nestes ACs; se precisar, é uma story própria ou um adendo).
- **`status = 'scheduled'` não vira `'published'' sozinho ainda:** não existe job que troque o status quando
  `release_at` passa — isso é do Épico 7 (Supabase Cron). Por enquanto, "agendado" só controla o que a RLS
  deixa visível (nada, até alguém trocar manualmente para `published`); não implementar nenhuma automação
  aqui, só o campo e o valor.

## Notas de desenvolvimento (implementação)
- **`requireAdmin(lang)`** (`src/lib/supabase/admin.ts`): novo helper, chamado uma vez no `layout.tsx` do admin.
  Redireciona para `/entrar?next=...` se não logado, ou para a home se logado mas não admin. O proxy continua
  cuidando só do login (story 1.3); este helper é quem checa o papel.
- **Texto do admin só em português:** é uma ferramenta interna do Gustavo, não parte da experiência trilingue
  do assinante (que continua sendo `name_pt`/`name_en`/`name_es` nas traduções do título, essas sim trilingues).
  Decisão alinhada com o que a story já previa em "Não inventar" — nenhum AC pedia o chrome do admin traduzido.
- **`saveTitle` faz upsert das traduções com `onConflict: "title_id,locale"`**, cobrindo criar e editar com a
  mesma função; só a tradução em português é obrigatória (como no restante do produto — ex.: cadastro na
  story 1.3 também assume `pt` como padrão).
- **Exclusão de temporada:** checa `count` de episódios antes de apagar (não confia só no erro do banco),
  conforme o risco já registrado na story; mostra um aviso (`?erro=temporada-com-episodios`) na própria página.
- **Erros do banco traduzidos** (`translateDbError`) para mensagens amigáveis (slug duplicado, troca de tipo
  bloqueada) em vez do texto cru do Postgres.

**Achados:**

  de agendamento — `title-form.tsx` mostra o `release_at` (UTC) cortado como se fosse hora local, e salvar
  sem tocar na data reinterpreta esse texto como hora local do servidor, deslocando o valor em 3h a cada
  edição (cumulativo). Não é hipotético: é determinístico, confirmado com um script.
- **TEST-002 (low, CONFIRMED):** o `pattern` do campo de slug no cliente é mais estrito (só minúsculas) do
  que a normalização do servidor (`.toLowerCase()`), bloqueando no navegador um slug válido com maiúsculas
  que o servidor aceitaria.
- **MNT-003 (low, CONFIRMED):** `translateDbError()` procura "kind"/"content" na mensagem de erro, mas a
  exceção real do trigger está em português e nunca bate com essa checagem — ramo morto (sem efeito prático
  hoje, pois o formulário nunca envia `kind` na edição).
- **TEST-003 (low):** `createSeason`/`deleteSeason` descartam o `error` do Supabase sem checar.
- **TEST-004 (low):** fluxo completo logado como admin ainda não testado por ninguém — falta de login de
  admin no ambiente, risco herdado da story 1.3, não novo.
