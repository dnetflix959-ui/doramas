# Story 1.5 — Produto só em português (remover inglês e espanhol)

**Épico:** 1 – Fundação (mudança de escopo, toca também telas do Épico 2) · **Status:** Done
**Executor:** @dev (+ @data-engineer no T1) · **Quality gate:** @architect

## História
Como Gustavo, quero que o produto seja só em português, para focar no público brasileiro em vez de manter
inglês e espanhol que não serão usados — conforme decisão registrada no PRD (`docs/prd/index.md`, nota de
escopo de 2026-11-06).

## Critérios de aceite
- [x] `locales` (`src/i18n/config.ts`) só tem `pt`; nada no app oferece trocar para inglês ou espanhol.
- [x] Seletor de idioma (`LanguageSwitcher`) removido da interface (não faz sentido com 1 idioma só).
- [x] Dicionários `en.json`/`es.json` removidos; só `pt.json` continua.
- [x] Formulários do admin que hoje pedem nome/sinopse em pt/en/es (título, episódio) mostram e salvam só o
      campo em português.
- [x] Formulário de gênero mostra e salva só o nome em português; `genres.name_en`/`name_es` deixam de ser
      obrigatórios no banco (migration), mas as colunas continuam existindo (ver Dev Notes/arquitetura).
- [x] As rotas continuam com o prefixo `/pt/...` (ver decisão em `docs/architecture/index.md`) — não remover
      o segmento `[lang]`, só reduzir a 1 idioma.
- [x] `npm run typecheck`, `npm run lint` e `npm run test` continuam passando depois da remoção.

## Escopo
- **Dentro:** `i18n/config.ts`, `LanguageSwitcher`, dicionários, formulários de título/episódio/gênero do
  admin (stories 2.2–2.4), migration relaxando `genres.name_en`/`name_es`.
- **Fora:** mudar a estrutura de rotas (`[lang]` continua existindo, só com 1 valor possível — menor risco
  que reescrever todas as rotas já construídas); apagar `en.json`/`es.json` de outros lugares que não
  `src/i18n/dictionaries/` (não há outros); qualquer coisa de cobrança/moeda (FR10 já ajustado no PRD, sem
  código ainda construído para isso).

## Dependências
- Depende de nada tecnicamente — é uma redução de escopo, não uma feature nova. Toca código das stories
  1.2 (idiomas), 2.2/2.3/2.4 (formulários do admin que pedem tradução).

## Complexidade
- **Baixa-média.** Principalmente remoção/simplificação; uma migration pequena (relaxar 2 colunas).

## Riscos
- **`genres.name_en`/`name_es` são `not null`** desde a story 2.1 — se o formulário parar de enviá-los sem
  antes relaxar a constraint, toda criação de gênero passa a falhar. A migration do T1 precisa rodar antes
  (ou junto) da mudança no formulário.
- **`title_translations.name`/`episode_translations.title` não têm esse problema:** já eram opcionais para
  en/es (só `pt` era obrigatório nos formulários desde as stories 2.2/2.3), então simplificar essas telas não
  precisa de migration — só remover os blocos de en/es do formulário.
- **Não apagar dados existentes:** se já houver alguma linha `en`/`es` em `title_translations`,
  `episode_translations` ou `subtitles` (pouco provável, catálogo ainda vazio), esta story não precisa
  apagá-las — só para de criar novas. Confirmar que o catálogo de teste está vazio antes (ou aceitar que
  ficam órfãs, inofensivas).

## Notas de desenvolvimento
- **Decisão de arquitetura já registrada** (`docs/architecture/index.md`): manter o prefixo `/pt/...` nas
  rotas (não remover `[lang]`) e manter as colunas/linhas por idioma no schema (`title_translations`,
  `episode_translations`, `subtitles`, `genres.name_en`/`name_es`), só parando de preencher/oferecer
  en/es — menor risco do que reescrever rotas e schema já testados dos Épicos 1 e 2.
- **Não apagar `title_translations`/`episode_translations`/`subtitles` do schema** — ficam como estão
  (unique por `locale`, FK, etc.); só os formulários do admin passam a gravar/mostrar só `pt`.
- **`switchLocalePath`/`hasLocale`/`localePath`** (`i18n/config.ts`) continuam funcionando sem mudança de
  assinatura — só o array `locales` fica menor; código que itera sobre `locales` automaticamente passa a
  iterar só `pt`.
- **Se sobrar algum uso de `LanguageSwitcher`** fora de `app-shell.tsx`, procurar antes de apagar o arquivo
  (`grep -rn "LanguageSwitcher"` em `web/src`).

## Notas de desenvolvimento (implementação)
- Ordem seguida exatamente como o @po recomendou: T1 (migration) antes de T6 (formulário de gênero) —
  testado criar um gênero só com `name_pt` com sucesso antes de tocar no formulário.
- `Record<Locale, string>` literais (`localeLabel` em `title-form.tsx` e `episode-content-form.tsx`) foram
  removidos — com `Locale` reduzido a `"pt"`, um objeto `{ pt: ..., en: ..., es: ... }` atribuído a
  `Record<Locale, string>` vira erro de excesso de propriedade no TypeScript; o `tsc --noEmit` pegaria isso
  na hora, então não tinha como esquecer.
- `app/[lang]/layout.tsx`, `proxy.ts` e `i18n/dictionaries.ts` não precisaram de nenhuma mudança —
  degradam sozinhos para 1 idioma (`generateStaticParams` devolve só `{lang:'pt'}`, `pickLocale()` sempre
  cai no `defaultLocale` para `accept-language` que não seja `pt`).
- `actions.ts`/`episode-content-actions.ts` mantiveram o `for (const locale of locales)` — já funcionava
  certo sem mudança (a lista agora só tem `pt`), conforme a própria story permitia ("o que for mais simples").
