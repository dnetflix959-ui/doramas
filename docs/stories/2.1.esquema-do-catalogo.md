## Critérios de aceite
- [x] Tabela `titles` (kind: `series`|`movie`, slug único, status: `draft`|`scheduled`|`published`, featured, release_at).
- [x] Tabela `title_translations` (title_id, locale `pt`|`en`|`es`, nome, sinopse) — uma linha por idioma e título.
- [x] Tabela `seasons` (title_id, número, só para `kind = 'series'`).
- [x] Tabela `episodes` (season_id, número, video_provider `youtube`|`bunny`, video_ref, duration_s, intro_start_s,
      intro_end_s, credits_start_s, release_at, is_free, status).
- [x] Tabela `episode_translations` (episode_id, locale, título, sinopse).
- [x] Tabela `subtitles` (episode_id, locale, url ou referência ao arquivo `.vtt`).
- [x] Tabelas `genres` e `title_genres` (muitos-para-muitos).
- [x] RLS em todas: leitura pública só de `titles`/`episodes` com `status = 'published'` (e, se agendado,
      `release_at <= now()`); escrita (insert/update/delete) só para admin (`is_admin()`).
- [x] Migration aplicada no projeto Supabase de teste; Security Advisor sem alertas novos (além dos 2 esperados — ver Dev Notes).

## Riscos
- **Slug único em `titles`:** usado nas landing pages (`/{idioma}/assistir/{slug}`, FR13) — definir a constraint
  de unicidade agora evita retrabalho quando a Épico 5 (landing pages) existir.
- **`seasons` só para séries:** decidir se é um `check` no banco (mais seguro) ou só validação no admin (mais simples);
  recomendado `check` no banco para não depender da story 2.2 fazer a validação certa.
- **RLS por data de lançamento:** `release_at` pode ser `null` (sem agendamento) ou no futuro; a política de leitura
  pública precisa tratar os dois casos sem expor episódios agendados antes da hora.

## Notas de desenvolvimento (implementação)

### Decisões de schema (fora dos critérios de aceite, registradas para o @architect no quality gate)
- **Filme = título com um episódio ligado direto.** Os critérios de aceite não diziam onde um filme guarda
  `video_provider`/`video_ref`/duração — só mencionavam isso em `episodes`. Decisão: `episodes.title_id`
  (novo, não estava no AC 4) é o caminho do filme; `episodes.season_id` continua o caminho da série. Um
  `check` garante que exatamente um dos dois está preenchido, e um trigger (`enforce_episode_parent`) garante
  que `season_id` só aponta para título `series` e `title_id` só para título `movie`. Índices únicos parciais
  garantem **um único episódio por filme** (`episodes_title_uidx`) e numeração sem repetição por temporada
  (`episodes_season_number_uidx`).
- **"Seasons só em séries" é um trigger, não um `check` simples:** um `check constraint` não pode consultar
  outra tabela; `enforce_season_requires_series()` (BEFORE INSERT/UPDATE) lê `titles.kind` e recusa se não for
  `series`. Mesma técnica para `enforce_episode_parent()`.
- **Gêneros sem tabela de tradução:** os critérios de aceite listam só `genres` e `title_genres` (2 tabelas,
  não 3). Em vez de criar `genre_translations`, `genres` tem `name_pt`/`name_en`/`name_es` como colunas —
  menos flexível que uma tabela de tradução, mas fiel ao que foi pedido; fácil migrar depois se precisar de
  mais idiomas.
- **`is_title_visible()` e `is_episode_visible()` são `SECURITY DEFINER`:** sem isso, a política de SELECT de
  `episodes` (que chama `is_episode_visible()`, que por sua vez faz SELECT em `episodes`) causa recursão
  infinita — a segunda leitura reaplica a mesma política RLS, que chama a função de novo, e assim por diante
  (erro real encontrado durante o teste: "stack depth limit exceeded"). Com `SECURITY DEFINER` a função roda
  como o dono da tabela e não é sujeita à RLS que ela mesma alimenta. O Security Advisor aponta as duas
  funções como "executável por anon/authenticated via RPC" — intencional (é assim que a política as chama) e
  sem risco: elas só devolvem um booleano para um id, sem vazar dados.

## Testes
- Migration aplicada sem erro no projeto de teste (`uktrllgocaxweijgbixm`).
- Harness SQL (`set local role`, revertido ao final — sem dados de teste no banco):
  anônimo e usuário comum não conseguem `INSERT` em `titles` (negado pela RLS); admin cria série com 1
  temporada, 2 episódios, tradução, legenda e gênero; `season` num título `movie` é recusado pelo trigger;
  episódio de filme via `title_id` funciona; episódio com `season_id` e `title_id` juntos é recusado; slug
  duplicado e número de episódio duplicado na mesma temporada são recusados; enquanto tudo é `draft`, anônimo
  não vê nenhum título/episódio (mas vê `genres`, que é referência pública); depois de publicar o título e o
  episódio 1, anônimo vê o título, o episódio 1 (não o episódio 2, que ficou `draft`), as traduções, a legenda
  e o `title_genres` — tudo via a cadeia de visibilidade (`is_title_visible`/`is_episode_visible`); usuário
  comum (não-admin) tem a mesma visão que o anônimo.
- Security Advisor do Supabase: sem alertas novos de RLS sem política; 2 alertas esperados e documentados
  (`is_title_visible`/`is_episode_visible` chamáveis via RPC — intencional, ver Dev Notes).
